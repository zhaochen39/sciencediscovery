# JiuwenSwarm Spine 三臂对照与试点回退验收

日期 2026-11-26（亚洲／上海）。环境为 WSL、本地 Runner、实际 JiuwenSwarm 0.2.6。真实模型用量来自实际供方报告，受控模型的固定用量用于验证记账。缓存读取量单列在审计文件中，Token 变化与费用变化各有独立口径。

## 判定

- **检查点恢复和长历史 Projection 进入限定场景的内部试点。** 文献恢复同时报告续跑与质控至交付的成本。长历史 Projection 按追问与全流程分别计量。两类优化分别启用。
- **Scope 观察和回退通过共用消息入口验收。** 观察只在指定试点实例开启。平台委派回执和 Evolve 链接根据可追溯性验收，性能单独记录。
- **已关闭 Scope 的 stdout 折叠保持默认关闭。** 以完整交付成本作为启用门槛。两个显式 Scope 动作本身都要消耗模型轮次。
- 用户任务类型和占比尚无采样，收益按场景报告。延迟按阶段、上游状态和成对重复判断。

## 对照口径

`original`（B0）取 `d684215a2fbbd366b6d455a941efa35cfc868ea9` 的源文件，开跑前校验了 906 个 API、包、锁文件等运行输入。`candidate-off`（C-off）取当前候选代码关闭 Spine，`candidate`（C-on）取同一候选打开被测能力。三组重新运行同一 JiuwenSwarm 后端、配置、固定输入与验收脚本，各臂创建独立数据目录。折叠实验的中间臂是 `candidate-no-fold`，保留显式 Scope 并关闭折叠。

每个合格臂要求 API Run 自然进入 `completed`，产物或回答通过独立断言，供方用量与调用账本一致。折叠开启组另外要求网关命中，受控组核对发送给模型的实际请求体。请求数是报告用量的模型轮次，供方传输重试单列。表内耗时为 API 提交至获取终态。百分比按 C-on 相对 B0 计算，折叠的额外对照标明比较对象。

## Projection 延迟诊断

旧批 `swarm-scope-final-20261126/scope-real/candidate/driver.log` 的约 201 秒追问包含一次上游 HTTP 首试失败。从初次请求到下一次发出约 191 秒，重试发出到首包约 7.899 秒。为区分本地 Projection 与上游等待，网关增加了投影计算耗时与首个上游流块埋点。

两次冻结追问使用同样的五份文件和逐字节校验过的受控读取轨迹。真实模型只执行追问。第二批逆序运行。受控源环节的固定 Token 不与真实追问用量相加。所有臂都回答 `FROZEN/155`，追问各一条模型请求、零 Shell。

首轮冻结追问实测候选 Projection 为 4 ms，七次网关历史处理在 0–4 ms。三臂供方首包为 8.631 / 7.506 / 2.745 秒，逆序重复为 4.662 / 1.825 / 2.122 秒，六次都没有传输重试。开启组和同版本关闭组的追问比值分别为 0.51×、1.00×，全真实来源追问为 1.55×（6.344 / 4.094 秒）。这些样本的延迟随首包波动。冻结初始轨迹后开启组两次都比同版本关闭组少约 5,100 输入 Token（约 11%）。

## 已关闭 Scope 的产物折叠

当前实现采用 SpineCodex 的关闭分支后保留交付摘要与证据引用的思路。只在显式 Scope 关闭成功后检查单个、已配对的 `run_shell` 结果。Runner 执行必须完成且退出码为 0，工具结果必须可证明未创建或改写文件，当前同 Scope 的 Artifact Version 内容必须与完整 stdout 的 SHA-256 一致。网关把后续请求中的长 stdout 替换成 Scope 交付发现、后续要求及产物版本，保留执行 ID、Runner 恢复字段和工具调用配对。原始工具结果仍在会话和执行日志，证据不匹配时发送原始结果。未知 JiuwenSwarm 封装、Runner 警告和不同执行 ID 均保持原样。

首跑暴露同一产物的重复关联冲突。已对同一会话、版本、Run、Scope 的关联做幂等处理。后续受控对照发现真实网关把 MCP 文本包装成单字段 Python repr，CAS 保存的真实模型输入复现了这一差异。现在只解包已知的字符串格式且只在折叠判定中使用，未知格式按原文发送。真实输出的 `recovery` 字段按原值保留。前几轮的失败、未命中和自然完成后校验失败均保留。

受控三臂在 `swarm-scope-fold-r5-20261126/tree-controlled` 自然完成，独立核验结果均为 `ASSAY/110`。开启组在后三次实际模型请求都命中。关闭 Scope 后第一次请求的消息 JSON 从 47,327 降至 42,313 字节（−10.59%），其中归档行被移除而交付结论依然可见。三臂模型请求为 5 / 7 / 7，Shell 均为 3。受控模型固定用量不用于推算生产 Token。

真实模型首轮修复版 `r5` 的同版本两臂都自然完成并通过原有的精确答案断言。开启折叠后命中 3 次，输入 326,062 → 318,351，输出 657 → 1,318，总量 326,719 → 319,669（−2.16%），请求均为 9，Shell 均为 3。耗时 55.913 → 106.028 秒（1.90×）。开启组有一次供方重试，该请求耗时 67.705 秒，关闭组最长供方请求为 8.196 秒。该轮原始臂答案包含正确结果码和额外解释，精确字符串断言失败，沿用失败判定。新一轮三臂在任务提示和 oracle 中明确允许简短解释，同时独立验证唯一结果码、三次 Shell 的完整 stdout、归档哈希和 Scope 关联。

## 回退与放行

回退测试从 Web 和桌面共用的 `/messages` SSE 入口发起。受控模型与真实模型各三臂都完成首个任务并答 `ASSAY/36`。候选开启臂随后关闭默认 Scope 与 Scope 总开关、重启 API、在同一会话继续作答 `14`，旧 Scope 树逐项读回一致。由此验证现有会话可以回到普通消息路径，既有审计记录仍可读。Web 和桌面构建加载实际 Scope 和产物的证据保存在之前的 `swarm-scope-ui-e2e-r3-20261126`。本轮测试范围为本地 Runner 与 API 重启后的新消息。Windows 安装包、远程 Runner、运行中 Swarm 进程重启和跨 Run 委派仍需各自的放行证据。

试点运维顺序如下。

1. 默认采用 C-off 配置。文献或已复验的恢复工作流由 `SCIENCE_AGENT_RESEARCH_RECOVERY_SESSIONS` 按专门会话准入。依检查点状态选择恢复方式时使用 `SCIENCE_AGENT_RESEARCH_RECOVERY_MODE=by-state`。沿用现有证据复核和本地工作区门禁。
2. 需要测量长历史追问的独立试点实例显式开启 `SCIENCE_AGENT_JIUWENSWARM_SCOPE_PROJECTION=1`。需要观察 Scope 时在单独配置的试点实例设置 `SCIENCE_AGENT_JIUWENSWARM_SCOPES=1` 和 `SCIENCE_AGENT_JIUWENSWARM_SCOPE_DEFAULT=observe`。观察与普通历史 Projection 的组合需要单独验证。
3. 每批检查自然完结率、独立产物校验率、输入与输出 Token、整任务用量、模型请求、Shell 与交付延迟分布。答案、产物或证据出错即停止扩大试点。耗时持续接近两倍时先从同负载样本拆解重试、首包和执行轮次。出现功能错误时取消对应开关或会话准入并按部署流程重启 API，使用原会话核对新消息与旧 Scope 可读。
