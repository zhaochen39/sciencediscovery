# 已验证文件状态的恢复交接验收 · 2026-11-25

## 实现与对照

新版从已验收的质控检查点生成结构化交接，核对质控产物的 SHA-256，并在复制出的恢复工作区重新检查质控文件。交接给出相对于 `run_shell` 工作目录的文件路径、版本、`site_qc.csv` 的实际列序及下一项待办。待展示时先单独读取当前版本完整表。已展示时给出分组的输入、分组列、均值列、等权口径和输出结构。模型继续执行分组、敏感性分析和报告，原始任务保持完整。结构化交接及首轮模型输入均有记录，验收器根据冻结文件和原始历史重建期望值。

用光伏数据做同检查点配对。完整历史恢复、原精简恢复、当前待办版、新交接版共用每组冻结点，分别在独立进程运行。当前待办版是本次改动的直接基线。真实模型计划六组，两种完整表状态各三组，组内串行，四组方法轮换执行位置。受控模型验证两种状态及最终交付，另外复制检查点注入文件缺失和版本不一致。

## 预定门槛

| 验收项 | 条件 |
|---|---|
| 正确性 | 六组四分支全部自然结束，五项交付产物独立验收通过，原始输入和质控文件逐字节一致，质控重写为零，待展示时先完整显示当前版本再分组 |
| 首次推进 | 新版至少 5/6 组在首个工具调用完成首项待办，待展示和已展示各至少 2/3 组 |
| 额外调用 | 新版较当前待办版和原精简恢复的去重额外调用总数均下降，额外调用沿用上轮的分组前无进展调用与重复整表输出之并集 |
| 交付耗时 | 新版较当前待办版、原精简恢复和完整历史恢复的故障后交付耗时配对中位数均下降 |
| Token | 相对完整历史恢复，首轮输入配对中位降幅至少 15%。业务和压缩请求用量对账，另列计入捕获的成本 |

## 受控模型与故障注入

两种状态各一组，四种恢复方式共 8/8 条交付自然结束并通过独立产物验收，质控文件保持字节一致，重写零次。新交接版在待展示组首个调用完整展示表格，已展示组首个调用写入分组。固定响应模型用于检验恢复顺序、交接字段和验收逻辑。

分别在冻结点副本删除 `site_qc.csv` 和追加换行模拟版本变化。两次恢复均以退出码 1 被检查点完整性校验拒绝，没有启动模型调用。独立审计回归用例覆盖失败的分组写入在首个调用时不能计入首次推进。

## 真实模型验收

WSL 使用 `DeepSeek-V4.1-Flash-1017` 完成六组冻结检查点，待展示和已展示各三组。四种恢复方式各 6/6 条、合计 **24/24 条交付**自然结束并通过独立验收。原始输入和质控输出均保持字节一致，质控重写零次。六个捕获均一次通过。业务请求 **159/159** 完成用量对账，其中捕获 16 个、完整历史 27 个、原精简 52 个、当前待办 33 个、新交接 31 个。原精简还有 **2/2 个压缩请求**完成对账，合计 16,617 输入、6,794 输出、23,411 总 Token，耗时 59.427 秒，均已纳入下表的全请求用量。

## 第三阶段启动与试运行

光伏工作区交接达到预定门槛后，进入仪器校准复验。校准用例需要独立验收质量和产物版本，复核在另一类任务里是否还能减少恢复后的探查并改善交付。两项成立即可启动第三阶段的工程工作，先将收益已验证的断点恢复接入正式运行时的内部开关。

向内部用户开放前，用正式入口验证跨进程恢复、重试幂等、错误检查点拒绝及回退、故障注入、轨迹可追踪和一键关闭。试运行首批限定在通过验收的工作流。原总规划的完整第三阶段还覆盖 Inline Scope、Trajectory 展示和质量门禁，按各项能力的验证结果推进。
