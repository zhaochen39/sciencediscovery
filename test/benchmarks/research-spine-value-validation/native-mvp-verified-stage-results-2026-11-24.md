## 实验协议

- **受控 E2E** 用本地 OpenAI 兼容脚本服务驱动真实 Native、Context、工具执行和产物验收。脚本提供的 usage 用于机制验证。
- **真实长任务** 使用合成的固定 cohort 与四阶段任务，阶段间实际读写六件产物。两组清洗成功后收到同一生成规则下的逐行审计。报告需引用前置产物，保留原始行数、列数、重复与缺失事实，并呈现风险差的方向和不确定性。
- **真实同前缀分叉** 在完成阶段 2 后冻结工作区、原始转录和完成证据。从同一份快照分别运行两个续跑任务，比较第一次请求服务端输入 Token，再核对两个分支的自然结束及最终产物。种子运行按设计暂停在阶段边界。
- **真实短任务** 只交付两项清洗产物，以检验无需压缩的场景。
- 长任务每批固定 10 对，配对内串行，奇偶对交换执行顺序。分片间并发，延迟受共享模型后端影响。两组使用相同的工具输出上限和验收反馈，正式成本依据模型服务的 usage。候选历史需同时节约 1,500 个估算 Token 和 10%。
- 推进门槛是全部 E2E 自然结束并通过产物校验，平均总 Token 下降至少 5%，至少 2/3 的配对输入 Token 下降，平均模型轮次和工具调用不增加。

## 真实模型长任务

模型为 `DeepSeek-V4.1-Flash-1017`。下表使用修正阶段校验后的 10 对。两组共 20/20 自然结束并通过六件产物验收。独立复算在 20/20 中确认清洗结果、风险差和 95% Wald 置信区间。113/113 条 usage 由模型服务报告。

| 指标 | Dynamic | Projection | 变化 |
|---|---:|---:|---:|
| 平均输入 Token | 46,655.40 | 36,211.30 | −22.39% |
| 平均输出 Token | 4,409.00 | 4,121.40 | −6.52% |
| 平均总 Token | 51,064.40 | 40,332.70 | −21.02% |
| 平均模型轮次 | 5.70 | 5.60 | −0.10 次 |
| 平均工具调用 | 4.70 | 4.60 | −0.10 次 |
| 平均耗时 | 221.01 s | 212.90 s | −3.67% |
| P95 耗时 | 414.49 s | 414.50 s | 约持平 |

8/10 对输入和总 Token 同时下降。9/10 条 Projection 轨迹至少投影一次，累计 27 次投影实际进入模型请求。每次平均减少 5,731 个估算历史 Token。验收按整批计算，包含总 Token 上升的第 4、5 对。第 4 对 Projection 在第 5 次请求首次投影，随后收到了报告不确定性校验反馈并完成修复。第 5 对 Projection 跳过了投影，轨迹中出现两次失败的 Shell 执行并最终恢复。

首批也有 20/20 通过，平均总 Token 下降 11.70%，输入下降 12.96%，7/10 对输入降低，平均模型轮次和工具调用各增加 0.10 次。首批阶段校验只接受去重后计算的中位数，还将数值相同的浓度文本视为不同值。部分合规产物因此拿不到阶段证据。按独立复算原有口径修正后，使用新工作区完整跑了第二批。两批保留初始产物、原始 usage 和轨迹。复测的在线报告校验仍有一例因 `95% CI` 缩写追加修复轮次。当前复现脚本识别该缩写，表中保留当时实际消耗。

## 受控、同前缀和短任务

| 实验 | 自然结束及产物验收 | 观测结果 |
|---|---|---|
| 受控正常 | 15/15 | Dynamic 到 Projection 的平均输入 Token 33,659.8 到 30,751，下降 8.64%。总 Token 33,815.8 到 30,907，下降 8.60%。输出、轮次和工具调用相同 |
| 受控报告字段故障 | 3/3 | 第 8 对的 `None rows` 故障通过产物反馈触发修复，三组均在 6 个模型轮次自然结束 |
| 受控清洗阶段故障 | 3/3 | 模型收到清洗失败响应，修复后通过产物验收，失败阶段未被投影 |
| 真实同前缀续跑 | 2/2 | 首次请求输入从 8,661 降到 5,546，下降 35.97%。两组均为 3 个模型轮次、2 次工具调用，续跑总 Token 从 33,711 降至 23,864，下降 29.21% |
| 真实短任务 | 4/4 | Projection 的 9 次决策均跳过。两组仍出现模型轨迹波动 |

同前缀复验的原始用户消息、续跑消息、系统提示、可用工具以及被替换工具结果之外的历史逐项一致。结构化证据和冻结的产物路径、版本及字段逐项一致。第一次分叉的 Projection 在第三次模型请求遇到服务端并发限流，未自然结束。复验沿用原始冻结快照，等待首批长任务结束后启动，并把两组的服务端重试上限设置为 8。日志保留首次失败和复验。

Context 单测 57/57，Native Context 集成 2/2，Native 单测 45/45，两个包的 TypeScript 检查通过。

## 决策

修正后的长任务达到本轮预设门槛，真实同前缀和短任务也通过。收益目前在采用逐行审计输出的固定跨阶段工作流取得。主实验和短任务共用同一数据集，第二套独立科研工作流仍需验证。下一步适合用现有显式实验模式，在会提交阶段完成证据的工作流做影子观察，并用独立任务复验，之后再评估小流量试用。
