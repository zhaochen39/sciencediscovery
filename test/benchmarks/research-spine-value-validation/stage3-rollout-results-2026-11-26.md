# ScienceDiscovery 第三阶段落地与对照验收

验收环境为 WSL、本地 Native API、本地 Runner。真实实验使用 DeepSeek-V4.1-Flash-1017。受控模型依固定脚本响应，科研命令在真实 Runner 中执行。原始框架基线为 `d684215a2fbbd366b6d455a941efa35cfc868ea9`。真实续跑的三条路径共享冻结历史、文件字节和用户任务，计时从 HTTP 入队到终态与 Usage API 对账。检查点捕获和服务启动单列。

## 工作区保护

按 Session、Run、Agent 和 Runner 关联执行，Run 取消会停止它拥有的本地 Shell。完成和取消竞态由同一 Runner 账本的终止证据确认。失联期间持久化 `shell-stop-unconfirmed`，后续试图接管工作区的普通 Run 或工作区写入受到门禁保护。Runner 恢复后，先确认前一个执行结束，再放行写入。中断前已经提交的部分产物可以审计。

| 正式 API 故障场景 | 验收结果 |
|---|---|
| Shell 活跃时取消 Run | 运行中拒绝新的文件写入。仅发送 Run 取消请求即可确认 Shell 终止。终态后释放探针，新增标记为 0。 |
| Runner 取消调用暂不可达 | Run 发布停止待确认记录，工作区写入返回 409。恢复同一 Runner 的取消能力后，确认终止并允许写入。 |
| 首个下游产物落盘后终止 API 进程 | 重启后 Run 为 `interrupted`。部分产物保留原字节，模型交付消息为 0。 |
| 正常结束后重启并重复提交 | 返回原 Run ID 和原消息。同请求重试新增模型请求和 Shell 执行均为 0。 |

四种场景经过重启后的轨迹和用量审计。对照中上一版正式 API 在 Run 取消后仍可观测到持续写入的 Shell，需要额外执行 Shell 取消。该观测来自同类故障驱动，适用于本地 Native 科研检查点。

## 恢复路由和内部试运行边界

`original` 指原始框架普通续跑。`full` 指当前正式检查点入口使用完整历史。`by-state` 指同一正式入口根据展示证据选择历史。试点模式要求显式指定 Session 和工作流，并核验质控表展示回执。关闭开关后，新检查点请求由 API 拒绝，已经接受的检查点按完整历史恢复并保留执行工具边界。普通续跑通过生产 API 的受控端到端验证。

验收采用双方对照。已展示组总 Token 相对 `full` 平均下降至少 20%。相对 `original` 的逐对耗时比例中位数增幅至多 10%。出现 1.8 倍耗时差距时保留首轮并复跑。每一条正常臂均检查自然终态、独立复算、质控文件指纹、展示顺序、重复展示、模型与 API 用量。单臂失败保留在分母。组均值仅使用三臂均通过的配对。

## 本地试点与回滚操作

1. 仅为通过准入的工作流设置 `SCIENCE_AGENT_RESEARCH_RECOVERY_MODE=pilot`，在 `SCIENCE_AGENT_RESEARCH_RECOVERY_PILOT_WORKFLOWS` 和 `SCIENCE_AGENT_RESEARCH_RECOVERY_SESSIONS` 分别填入明确的工作流及 Session ID。重启服务后通过当前 Run API 提交。准入时还会校验同一检查点对应的质控回执、表格内容和工作区版本。两项名单分别配置，缺少任何一项都无法启用。
2. 用同一个 Run ID 对齐 Trajectory、Run 事件、Usage 和 Shell 执行记录。逐条保留选路、证据退出与恢复、交付复算、停止确认、开始和结束时间、输入和输出用量以及重复展示次数。已展示场景的收益只能与同入口 `full` 对照归因于选路。与 `original` 对照得到整条检查点路径的变化。
3. 发生错误交付、取消后写入、重复副作用或反复出现 ≥1.8× 的慢样本时，移除对应 Session 或工作流的授权。移除 `SCIENCE_AGENT_RESEARCH_RECOVERY_MODE` 可关闭整个入口。新请求通过普通 Run 路径续跑。已接受但仍排队的检查点在重新选路时使用完整历史。运行中若中断，先确认旧 Shell 终止，再根据 Trajectory 和工作区复算部分产物。遇到 `RESEARCH_SHELL_STOP_UNCONFIRMED` 时先恢复原 Runner 的可达性，再重试提交或写入。

计时包含模型供应商重试和所有工具等待。冻结点的采集发生在计时窗口之前。历史冻结点用于复验，新的冻结点用于检查结果是否能跨历史复现。试点门槛针对本地单实例 Native。对真实内部用户的任务分布、用量和交付质量仍需实际试用数据。

## Trajectory 与证据复用

检查点编号、路由原因、证据退出和恢复、交付复算、Shell 停止状态均保留在现有 Run 事件流。Trajectory 使用同一顺序读取这些记录。真实 API 重启后再次读取明细，检查来源 Run、检查点摘要及动作一致性。测试覆盖同时间戳事件的顺序，顺序由事件序号确定。

Node Memory 原型在通过独立科研复算的运行中重新打开持久化存储，逐项匹配 Workspace File Revision 和 CAS 内容字节。光伏、校准各验证 3 项文件版本。光伏对照用同一 Run 的已验证产物完成分组最高值复核。原型通过 CAS 引用解析下一步所需结果。样本包含工作区文件版本，Artifact 和 ScienceMemory Graph 实际连边需要另行验证。

Inline Scope 的研究原型用同一 Run 分别完成两项独立计算，直接基线通过原有 `task` 创建两个独立 Native 子 Agent。两条路径都走真实 API 和模型，父 Run 输出经固定真值校验。Spawn Receipt 从重启后可读的持久化子 Run 状态构建 CAS 引用。交换分支顺序时生成相同摘要。受控失败样本保留成功分支的结果和失败分支的校验诊断。该验收针对只读、无外部副作用的计算步骤。
