# ScienceDiscovery 第三阶段验收报告

日期 2026-11-25，北京时间。验收环境为 WSL、Native 执行器、本地 Runner。真实模型使用 `DeepSeek-V4.1-Flash-1017`。原始对照提交为 `d684215a2fbbd366b6d455a941efa35cfc868ea9`。

## 验收决策

保留已通过验证的断点恢复实现，保持默认关闭。本轮量化结果支持对**已展示且有可核验工具证据**的检查点继续使用同一机制做内部实验。待展示分支走完整历史，光伏用例出现输出 Token、调用次数和耗时回退。当前样本和并发故障覆盖不足以开放常规使用。

- 将 SpineCodex 的证据投影落实到已有的 Session 和 Run。持久化检查点绑定工作区、源 Run、助手消息、任务和输入文件版本。原始历史可重放。只有已验证的独立下游产物才能让展示证据退出模型视图。后续无法确认有效性会恢复证据。
- 正式入口执行输入复算、保护文件版本检查、展示顺序与交付复算。Run 轨迹记录选路、证据退出或恢复以及交付通过。同一 API 实例收到并发重复提交时返回同一个 Run。
- Inline Scope、通用 Node Memory、Scope 树和更大的试用范围本轮暂缓。两个收益用例的正式对照没有实际子 Agent 用量，无法测出 Inline Scope 对 AgentRun 或工作区启动的作用。现有实现覆盖两种明确的科研工作流，通用节点记忆仍缺乏对照数据。

## 对照口径

| 实验臂 | 运行内容 | 用于回答 |
|---|---|---|
| `original` | 用原始提交的 Dynamic 默认历史和普通续跑入口 | 整套改动相对无 Spine 技术的变化 |
| `full` | 用当前正式检查点入口、完整历史和工作流工具筛选 | 同一套正式入口下的对照 |
| `by-state` | 与 `full` 共用入口及工具筛选，按证据状态选择历史和交接 | 按状态恢复带来的额外变化 |

正式 API 对照给三个隔离工作区放入同一冻结点的历史与产物，计时从 HTTP 提交续跑至 Run 达到终态。第一个阶段的捕获开销不计入续跑。真实模型自然结束、独立复算、展示顺序、质控文件保护和 Token 对账均检查。输入、输出和总 Token 取模型报告的用量，与 Run 记录和 Usage API 对账。耗时是实际交付时间，包含请求和工具执行。模型请求统计业务、压缩和辅助请求。工具调用统计主 Run 的工具完成事件，含失败调用。重复展示是已看过当前完整质控表后，又在工具结果中输出同版本整表。Python 为拟合、分组读取表是必要的数据访问。原始路径的写入检查使用字节对照和可见的工具副作用。候选路径额外检查文件身份和修改时间，可拒绝同字节重写。

### 验收结果

最终正式批 4 个冻结点各跑三路，**12/12** 条真实模型续跑自然结束，独立复算、展示顺序、输入文件保护和用量对账均通过。重复整表展示、质控重写和模型传输重试均为 0。相对原始提交，候选模型请求下降 **12.50%**，工具调用下降 **27.27%**。四组耗时配对中位快 **6.724 秒**，最大回退为光伏待展示的 **1.507×**。校准已展示的输出 Token 增加 **10.59%**，耗时增加 **12.949 秒**。光伏待展示的输出增加 **36.78%**，多两次模型请求和两次工具调用，耗时增加 **37.861 秒**。这些结果支持 Token 收益，耗时收益随工作流和检查点变化。

相对当前完整历史，两个已展示点的总 Token 分别下降 **51.67%** 和 **34.35%**，平均降 **42.79%**。光伏快 **11.135 秒**，校准慢 **31.618 秒**。这里两侧使用相同入口和工具策略。待展示两侧都走完整历史，观测差异不能归因于证据精简。原始对照的整套收益包含工具目录差异。四个冻结点来自两类用例，结果适用范围限于本轮模型与工作流。

本批候选相对原始及完整历史的最大回退分别为 **1.507×** 和 **1.569×**，均低于 **1.8×** 复跑线。早期校准候选相对原始的 **1.891×** 伴随质控重写，原日志保留。相同冻结点修正后分别测得 **0.685×** 和 **1.174×**。复验顺序保存在各组 `arm-order.txt`。

## 复现与日志

以下命令在 WSL、仓库根目录执行。`baseline` 指向固定原始提交的独立 checkout，应先安装锁定依赖并构建工作区包。冻结捕获目录包含 `checkpoint-index.json`，目标目录须为新目录。实验密钥通过脚本从用户提供的 `env.sh` 加载。

```bash
b=test/benchmarks/research-spine-value-validation
export TMPDIR="$HOME/.cache/science-spine-tmp"
mkdir -p "$TMPDIR"
baseline=$(cat .tmp/stage3-linux-baseline-path)
git -C "$baseline" rev-parse HEAD

SCIENCE_SPINE_BASELINE_ROOT="$baseline" \
SCIENCE_SPINE_CASE=solar \
SCIENCE_SPINE_LOG_DIR="$b/logs/reproduce-native-solar" \
bash "$b/run-state-recovery-wsl.sh"

bash "$b/run-formal-recovery-wsl.sh" \
  "$b/logs/stage3-original-solar-r2/pair-2/capture" \
  "$b/logs/reproduce-formal-solar" "$baseline" by-state
python3 "$b/report-formal-recovery.py" "$b/logs/reproduce-formal-solar" --require-pass
```

受控正式入口可用下面的命令复跑。`pass` 与 `source-run` 预期完成，`rewrite` 与 `skip-display` 预期被运行时拒绝。`source-run` 和 `rewrite` 使用已展示的第 2 个冻结点，`skip-display` 使用待展示的第 1 个冻结点。

```bash
capture="$b/logs/stage3-original-solar-r2/pair-2/capture"
checkpoint_id=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["id"])' "$capture/checkpoint-index.json")
output="$b/logs/reproduce-formal-controlled"
mkdir -p "$output/by-state"
SCIENCE_SPINE_FORMAL_CONTROLLED=source-run pnpm exec tsx "$b/run-formal-recovery.ts" \
  "$capture/$checkpoint_id" "$output/by-state" by-state > "$output/by-state/driver.log" 2>&1
python3 "$b/report-formal-recovery.py" "$output"
```
校准的 Native 工作流名使用 `calibration-review`。正式 API 使用对应的 `stage3-original-calibration-r2` 冻结目录。正式用例的 `result.json` 记录终态和用量，`driver.log` 记录模型 SSE 请求统计。`data-dir.txt` 指向 WSL 内的独立数据目录，长期保留的轨迹位于 `run-events/`、`context-traces/` 和 `logs/run.log`。`formal-audit.jsonl` 从这些文件和工作区产物复算。使用新的日志目录可保留原始尝试。
